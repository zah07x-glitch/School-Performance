# منصة الأداء المدرسي الذكية

## حالة التنفيذ (نسخة تأسيسية 0.1.0)

**منفذ:** تطبيق React/TypeScript بواجهة عربية RTL متجاوبة، قائمة تنقل للوحدات الأربع عشرة، لوحة قيادة بلا أرقام مختلقة، إعدادات مدرسة قابلة للتعديل ومحفوظة محليًا، وضع فاتح/داكن، هيكل قاعدة بيانات أولي مع RLS، وملف نشر GitHub Pages.

**غير منفذ بعد:** تسجيل الدخول وربط Supabase الفعلي، تخزين الملفات، OCR، استخراج وتحليل البيانات، التحليل الإحصائي، الذكاء الاصطناعي، توليد الخطط، المتابعة، التصدير، اختبارات التكامل، تدقيق الأمان. صفحات الوحدات غير المنفذة تُظهر حالتها صراحةً. لا تستخدم هذه النسخة لتخزين بيانات طلاب حقيقية.

## التشغيل المحلي

```bash
npm install
npm run dev
npm run build
```

## قاعدة البيانات

1. أنشئ مشروع Supabase خاصًا بالمدرسة.
2. راجع `supabase/migrations/001_initial.sql` ثم نفذه في SQL Editor.
3. أنشئ المستخدمين والمدرسة والعضويات عبر خدمة خلفية ذات صلاحيات محمية؛ لا تُدخل بيانات الطلاب قبل اكتمال الضوابط الأمنية.
4. ملف `.env.example` يوضح المتغيرات العامة. لم تُربط الواجهة بقاعدة البيانات في هذه النسخة.
5. لا تنشر مفاتيح service_role أو مفاتيح مزودي الذكاء الاصطناعي في المتصفح أو GitHub.

## النشر على GitHub Pages

1. أنشئ مستودعًا باسم `school-performance-platform` على GitHub.
2. ارفع محتويات المشروع إلى فرع `main`.
3. من Settings → Pages اختر Source: GitHub Actions.
4. سيبني workflow الواجهة وينشرها. إذا غيّرت اسم المستودع، حدّث `base` في `vite.config.ts`.
5. GitHub Pages يستضيف الواجهة فقط؛ أي بيانات حساسة أو عمليات AI تتطلب خدمات خلفية آمنة منفصلة.

## خارطة التنفيذ

1. الهيكل والهوية والتنقل: **منفذ**.
2. المصادقة والصلاحيات: مخطط قاعدة بيانات أولي فقط.
3. استيراد الملفات والتحقق: غير منفذ.
4. محركات التحليل: غير منفذة.
5. محرك AI وRAG: غير منفذ.
6. الخطط الثلاث: غير منفذة.
7. المتابعة والشواهد: غير منفذة.
8. التقارير والتصدير: غير منفذة.
9. اختبارات الأمان والجودة: غير منفذة.
10. إعداد نشر الواجهة: منفذ، والنشر الفعلي يحتاج مستودعًا وتفويضًا.

## خصوصية البيانات

حفظ إعدادات المدرسة حاليًا يتم في localStorage فقط؛ لا تستخدمه لحفظ بيانات حساسة. SQL يطبق سياسات قراءة وعزل أولية؛ ليس تدقيقًا أمنيًا مكتملًا. صلاحيات العضويات والتخزين والتدقيق يجب أن تُنفذ في الخادم قبل الاستخدام الإنتاجي.
